# STORY ENGINE v5.1
**Status:** ACTIVE / CORE
**Migration:** V4.1 → V5.1 — LOSSLESS CONTENT RECOVERY

## 1. Flow

`CAST → SOURCE MANIFEST → SCENARIO → SCENOPIS → ACCEPT/CORRECT → GENERATION CONTROL`

For image generation:

`SOURCE → LOCKS → SCENOPIS → PRE-GEN → FINAL CONSISTENCY → GENERATE → PER-PANEL CHECK → PASS/FAIL`

---

## 2. Source / Cast

Characters are consciously selected.

There is no default random identity.

For every significant character:

- establish an explicit Active T-POSE Source,
- perform the required full read,
- create an independent fresh Character Lock.

T-POSE defines appearance.

Scene, scenario, personality, outfit and dialogue never redefine the body or visual identity.

Every character in a multi-character scene has an independent identity gate.

---

## 3. Source Manifest

Before a series/story, establish:

```text
CHARACTER ID
ACTIVE T-POSE SOURCE
CHARACTER LOCK
STYLE / STYLE LOCK
SCENE / STORY PARAMETERS
LAYOUT
FORMAT
CAMERA / FRAMING
PEGI, IF ACTIVE
AUTHORIZED TRANSFORMATIONS
REFERENCE ELEMENTS
SCENE CONTINUITY
```

No previous generation is used as a substitute source.

---

## 4. Scenario Model

A scenario may define:

- genre,
- style,
- place,
- time,
- atmosphere,
- action,
- character count,
- outfit,
- camera,
- framing,
- format,
- layout,
- dynamics,
- props/requisites,
- reference elements,
- interaction,
- dialogue,
- emotion,
- continuity,
- locks,
- authorized transformations.

Scene parameters define the scene, not the character's source anatomy.

---

## 5. Full Read

Every selected character requires full T-POSE text/OCR + complete visual read.

Read includes, where applicable:

- face,
- eyes,
- hair,
- ears,
- skin/surface,
- silhouette,
- proportions,
- critical anatomy,
- integral anatomy,
- laterality,
- fixed/removable elements,
- source-defined transformations and notes.

If a critical feature cannot be established:

> **STOP → NIE ZGADUJ.**

---

## 6. Scenopis

A scenopis is required before generating a series of pages/images when the workflow calls for it.

It establishes:

- page/scene sequence,
- Action Track,
- Emotion Track,
- panel intent,
- framing,
- dialogue where applicable,
- continuity,
- narrative progression,
- character interaction,
- ending/wrap-up or punchline where applicable.

Emotions must be visible in the image.

They are not automatically delegated to speech balloons.

---

## 7. Personality

`PERSONALITY → REACTION / DECISION / DIALOG / BEHAVIOR / SCENOPIS`

Personality can influence behavior, reactions and decisions.

Personality is not an independent appearance source.

---

## 8. Scene Continuity Lock

Scene Continuity may track temporary scene state, including:

- hair state,
- moisture,
- dirt,
- outfit state,
- props,
- temporary damage,
- other scene-only changes.

Scene Continuity never updates:

- T-POSE,
- Character Lock,
- permanent anatomy,
- permanent identity.

---

## 9. Story / Page Constraints

Preserve the operational story limits:

- maximum **5 content frames per page**,
- flexible framing,
- every page checked separately,
- every significant frame checked separately,
- emotional continuity,
- narrative continuity,
- 5–10 page short-story target where that workflow is requested,
- narrative wrap-up/punchline where applicable.

A different page count is permitted when explicitly requested by the user or current workflow.

---

## 10. Pre-Generation Modes

### Quick Pre-Gen

May shorten the visible preparation report.

It never removes required source/full-read/Lock checks.

### Full Pre-Gen

Provides the complete operational report when required by the workflow or diagnostic state.

Both modes use the same underlying control requirements.

---

## 11. Page / Frame Generation

Each page and significant frame is controlled separately.

A correct frame does not pass the page.

A correct page does not pass the story.

Preserve:

- scene parameters,
- character identity,
- continuity,
- layout,
- style,
- dialogue placement,
- action/emotion tracks.

---

## 12. Selective Regeneration

If only selected frames fail:

`FAILED FRAME → SOURCE/LOCK CHECK → CORRECTION → NEW PRE-GEN → REGENERATE FAILED FRAME(S)`

Valid frames may retain their valid scene parameters and continuity state.

A valid previous frame remains a result, not an identity source.

A failed frame never becomes a reference.

---

## 13. Complexity

The more complex the scene, the more rigorous the control.

Check especially:

- hands,
- limbs,
- integral anatomy,
- tail,
- spatial relations,
- pose/contact,
- props,
- interactions,
- laterality,
- continuity,
- identity of every character.

Dynamic action is not an excuse for anatomical errors.

---

## 14. Locks

Available story locks include:

- Interaction Lock,
- POV Lock,
- Dialog Lock,
- Narrative Lock,
- Hard Scene Lock,
- Hard Object Lock,
- Reference Element Lock,
- Authorized Transformation Lock,
- Scene Continuity Lock.

Locks protect the declared scene state.

They do not replace the T-POSE or Character Lock.

---

## 15. Outfit / Anatomy

Outfit adapts to anatomy.

Outfit changes do not:

- change anatomy,
- change real proportions,
- normalize unusual anatomy,
- alter identity.

Authorized transformations are the only exception within their explicitly declared scope.

---

## 16. Total Random

`TOTAL RANDOM` may randomize only presentation and scene variables explicitly allowed by the active command.

It never randomizes:

- character identity,
- active T-POSE,
- Character Lock,
- critical anatomy,
- protected proportions,
- integral anatomy.

---

## 17. Generation Control

Every story passes through Generation Control:

`SOURCE → LOCKS → SCENOPIS → PRE-GEN → FINAL CONSISTENCY → GENERATE → PER-PANEL CHECK → PASS/FAIL`

The explicit generation command remains required unless an active workflow explicitly states otherwise.

---

## 18. FAIL

`FAIL → IDENTIFY ERROR → RETURN TO ACTIVE SOURCE → CORRECTION → NEW PRE-GEN → GENERATE`

Failed output never becomes a source/reference.

PASS also does not create a new source automatically.

---

## 19. PEGI 16

PEGI is a presentation layer.

It does not override:

- source priority,
- T-POSE,
- Character Lock,
- anatomy,
- reference locks,
- safety constraints.

When PEGI 16 is active, apply the active PEGI protocol, including its required presentation marking/adaptation and post-check.

---

## 20. Final Story Gate

Before accepting a story/page:

- identity is correct for every character,
- Character Locks are intact,
- anatomy is correct,
- authorized transformations are respected,
- story/scenopis continuity is correct,
- page/frame structure is correct,
- layout is correct,
- style is correct,
- PEGI requirements are fulfilled where active,
- failed outputs have not been reused as sources.

**END OF DOCUMENT**
