# UNIVERSAL TEST ENGINE v5.1
**Status:** ACTIVE / CORE
**Migration:** V4.1 → V5.1 — LOSSLESS CONTENT RECOVERY

## 1. Role
Common execution skeleton for Position, Morph, Emotion, Style and future modules.
It does not replace specialist module rules.

## 2. Test Baseline Lock
Every test explicitly records:
- FIXED PARAMETERS,
- CHANGED PARAMETER,
- RANGE,
- CRITERION,
- presentation constraints.

## 3. Standard
`SOURCE → T-POSE → FULL READ → CHARACTER LOCK → BASELINE LOCK → TEST → PRE-GEN → FINAL LOCK → GENERATE → GATES → PASS/FAIL`

## 4. One Variable
One principal controlled variable. Other parameters stay fixed unless explicitly included.

## 5. Gates
Identity / Anatomy / Parameter / Presentation.
Identity and critical Anatomy are never waived because Parameter or Presentation passed.

## 6. Specialist modules
Universal Engine supplies the common gates.
Specialist modules retain all their concrete rules, values, panel counts, scales, default presentation, physics, emotion logic, labels, commands and failure criteria.

## 7. PASS
Applies only to the concrete result. It never creates T-POSE, Character Lock or source.

## 8. FAIL
`FAIL → SOURCE → CORRECTION → NEW PRE-GEN → NEW GENERATION`
FAIL is never a reference.

## 9. Important migration rule
> **REFRACTOR ≠ REDUCE**
Scalanie dokumentów może zmienić strukturę, ale nie usuwa obowiązującej treści operacyjnej.
